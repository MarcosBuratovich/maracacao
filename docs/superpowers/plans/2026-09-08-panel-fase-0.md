# Panel del cliente · Fase 0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar el repo listo para que exista un panel de edición: una compuerta de publicación que no puede recursar, una mina de producción desactivada, y fuera el código muerto que el panel expondría por error.

**Architecture:** Nada de esto construye el panel. Son los cuatro arreglos que el panel da por supuestos: (1) que `pnpm build` corra los 677 tests antes de publicar — hoy no lo hace, y ponerlo ingenuamente sería una recursión porque un test ya construye el sitio; (2) que un texto con `<` no pueda matar el JavaScript de la página; (3) que los tests no exploten cuando un nombre traiga paréntesis; (4) que no quede copy muerto que la clienta pueda editar sin que cambie nada.

**Tech Stack:** Astro 7 (estático, sin adapter), Vitest 4, TypeScript 6, pnpm, Vercel (Pro), Node 22.

**Spec:** `docs/superpowers/specs/2026-09-08-panel-cliente-design.md` — sección `0` de la arquitectura, más `§0.1` a `§0.4`.

```ts
/*
 * `esc()` existe porque cuatro tests interpolaban contenido crudo en un
 * `new RegExp`. Mientras ningún nombre tuvo paréntesis nadie lo notó; con
 * el panel, la clienta puede escribir «Lima (con chile)» y el patrón
 * dejaría de matchear sin decir por qué. El escape saca esa restricción
 * de vocabulario, que nunca fue una decisión de marca: era un bug.
 */
import { describe, it, expect } from 'vitest'
import { esc } from './regex'

describe('esc()', () => {
  it('deja interpolar un nombre con paréntesis', () => {
    const nombre = 'Lima (con chile)'
    expect(new RegExp(`>${esc(nombre)}<`).test(`>${nombre}<`)).toBe(true)
    // Sin escapar, los paréntesis son un grupo: el patrón matchea
    // «>Lima con chile<», que es otra cadena.
    expect(new RegExp(`>${nombre}<`).test(`>${nombre}<`)).toBe(false)
  })

  it('deja interpolar un nombre con signo de pregunta', () => {
    const nombre = '¿Chamoy?'
    expect(new RegExp(`>${esc(nombre)}<`).test(`>${nombre}<`)).toBe(true)
    expect(new RegExp(`>${nombre}<`).test(`>${nombre}<`)).toBe(false)
  })

  it('no toca lo que no es metacarácter', () => {
    expect(esc('Fresas & chile')).toBe('Fresas & chile')
    expect(esc('Jengibre y naranja')).toBe('Jengibre y naranja')
  })
})
```

```ts
/**
 * Serializa datos para un `<script type="application/json">` inyectado con
 * `set:html`, que no escapa nada.
 *
 * `<` solo puede aparecer dentro de un string de JSON (los caracteres
 * estructurales son `{}[]",:` y los literales), así que reemplazarlo en
 * toda la cadena es seguro. `<` es un escape válido de JSON y vuelve

 * script antes de tiempo y el `JSON.parse` del otro lado tira.
 */
export const jsonParaHtml = (datos: unknown) =>
  JSON.stringify(datos).replace(/</g, '\\u003c')
```
