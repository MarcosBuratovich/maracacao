# Panel fase 7 — que el CMS se entienda · Plan de implementación

> **Para quien lo ejecute:** SUB-SKILL REQUERIDA: usar
> superpowers:subagent-driven-development (recomendado) o
> superpowers:executing-plans para implementar tarea por tarea. Los pasos usan
> casillas (`- [ ]`) para ir marcando.

**Objetivo:** Que la clienta encuentre lo que busca entre 692 campos, viendo
nunca más de un puñado a la vez, y que pueda agregar y borrar ítems donde
puede terminar el trabajo sola.

**Arquitectura:** Cinco puertas reemplazan a las catorce secciones; adentro de
cada puerta, lista de ítems al costado (cajón en el celular) y formulario del
ítem elegido. Todo el trabajo es del lado del panel: `src/contenido/**` y
`src/servidor/**` no se tocan, así que no hay que re-empaquetar `api/panel.js`.

**Stack:** Astro 7 · React 19 · TypeScript 6 · Vitest 4 · pnpm 11.2.2

**Spec:** `docs/superpowers/specs/2026-09-23-panel-fase-7-diseno.md`

## Restricciones globales

- **La regla del borde**: `src/servidor/entradas/**` es el ÚNICO lugar que lee
  `process.env`, toma `fetch` del global o toca el reloj de pared. Esta fase no
  toca `src/servidor/**` en absoluto.
- **Capa isomórfica**: `src/contenido/**` no importa `node:*` ni Astro. Esta
  fase no la toca.
- **Invisibles como escape (`\u00a0`), nunca pegados.** Restricción dura. Barré
  cada archivo tocado Y el mensaje de commit antes de darlo por bueno; si se
  escribe un escape por shell, la decodificación lo puede convertir en el
  carácter real.
- **Registro del idioma**: lo que lee la clienta va en español mexicano sin
  jerga técnica (nada de «sha», «commit», «deploy», «branch», «token», «API»,
  «campo», «JSON»). Hay un guardián automático, `jergaEn()`, exportado desde
  `src/servidor/estado.ts`. Los comentarios para Marcos van en castellano
  rioplatense y explican POR QUÉ, no qué.
- Ningún secreto, contraseña ni token en código, tests, logs ni comentarios.
- **Los tests no dependen del tiempo real**: reloj inyectado o
  `vi.useFakeTimers()`. Una fecha absoluta comparada contra el reloj del
  sistema ya rompió `main` una vez.
- **Ningún test afirma sobre el TEXTO del archivo fuente.** Se renderiza y se
  afirma sobre lo que se ve. Seis tests que hacían eso dejaron pasar una página
  que nunca funcionó en un navegador real.
- `pnpm build` = `astro build && vitest run && astro check` es el
  `buildCommand` de Vercel: **cualquier test que falle bloquea la publicación
  de la clienta.**
- Base al empezar: **1516 tests en 67 archivos**, typecheck `0 errors / 0
  warnings / 3 hints`.

```ts
/*
 * Las cinco puertas del panel (fase 7, decisión D1 del diseño).
 *
 * La navegación deja de seguir las secciones de la PÁGINA y pasa a seguir
 * las cosas que la clienta administra. El mapa vive acá y no en el esquema
 * a propósito: las puertas son una decisión de la interfaz, y
 * `src/contenido/**` no tiene por qué enterarse de cómo se dibuja el panel.
 */
import type { CampoEditable, Seccion } from './campos'

export type Puerta = 'productos' | 'textos' | 'fichas' | 'negocio' | 'invisible'

export const PUERTAS: readonly Puerta[] = ['productos', 'textos', 'fichas', 'negocio', 'invisible']

export const ETIQUETA_DE_PUERTA: Readonly<Record<Puerta, string>> = {
  productos: 'Productos',
  textos: 'Textos del sitio',
  fichas: 'Fichas técnicas',
  negocio: 'Contacto y negocio',
  invisible: 'Lo que no se ve',
}

/*
 * Las fichas llevan advertencia y el resto no. No es decoración: ahí adentro
 * hay declaraciones que tienen que coincidir con el empaque impreso y con lo
 * que se declara ante la autoridad. Entrar ahí no puede sentirse igual que
 * corregir una errata de la portada.
 */
export const AVISO_DE_PUERTA: Readonly<Partial<Record<Puerta, string>>> = {
  fichas: 'Lo que cambies aquí tiene que decir exactamente lo mismo que la envoltura impresa.',
  invisible: 'Esto no se ve en la página: son las descripciones de las imágenes para quien no puede verlas, y lo que aparece en los buscadores.',
}

const PUERTA_DE_SECCION: Readonly<Record<Seccion, Puerta>> = {
  productos: 'productos',
  sabores: 'productos',
  portada: 'textos',
  catar: 'textos',
  recetas: 'textos',
  nosotros: 'textos',
  preguntas: 'textos',
  pie: 'textos',
  'no-encontrada': 'textos',
  fichas: 'fichas',
  contacto: 'negocio',
  negocios: 'negocio',
  accesibilidad: 'invisible',
  buscadores: 'invisible',
}

export function puertaDe(seccion: Seccion): Puerta {
  return PUERTA_DE_SECCION[seccion]
}

export function camposDePuerta(todos: readonly CampoEditable[], puerta: Puerta): CampoEditable[] {
  return todos.filter((c) => puertaDe(c.meta.seccion) === puerta)
}
```
